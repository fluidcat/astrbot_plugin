# 统一连接服务插件 (Unified Connection Service Plugin)

## 概述

统一连接服务插件为 AstrBot 提供了完整的用户间连线和人工客服系统，允许用户之间直接连线或请求人工客服服务。

## 功能特性

### 🔗 用户间连线
- 通过 `/连线` 命令发起用户间连线请求
- 支持连线请求的接受和拒绝
- 实时双向消息转发
- 灵活的连接管理和结束

### 🔔 客服服务
- 通过 `/转人工` 命令快速请求人工服务
- 管理员可通过 `/客服接入` 命令接入用户会话
- 专业的客服流程和状态管理

### 💬 统一消息系统
- 双向消息转发，支持所有平台
- 实时通知系统
- 消息历史记录
- 智能消息路由

### 🔄 智能管理
- 完整的连接生命周期管理
- 自动超时处理和清理
- 全面的状态监控
- 异常恢复机制

## 命令列表

### 用户间连线命令

| 命令 | 说明 | 用法示例 |
|------|------|----------|
| `/连线` | 发起用户间连线请求 | `/连线 user123 请求一起学习` |
| `/同意连线` | 接受连线请求 | `/同意连线 abc123ef` |
| `/拒绝连线` | 拒绝连线请求 | `/拒绝连线 abc123ef` |
| `/结束连线` | 结束当前连接 | `/结束连线` |
| `/连接状态` | 查看连接状态 | `/连接状态` |

### 客服服务命令

| 命令 | 权限要求 | 说明 | 用法示例 |
|------|----------|------|----------|
| `/转人工` | 普通用户 | 请求人工客服服务 | `/转人工 登录问题` |
| `/客服接入` | 管理员 | 接入指定的客服会话 | `/客服接入 abc123ef` |
| `/连接状态` | 管理员 | 查看所有活跃连接 | `/连接状态` |

## 使用流程

### 1. 用户请求客服

```
用户: /转人工 我遇到了登录问题
Bot: ✅ 已为您创建客服会话
     会话ID: abc123ef
     正在通知客服，请稍候...
     使用 /退出客服 可以退出会话
```

### 2. 管理员查看等待中的会话

```
管理员: /客服状态
Bot: 📊 客服系统状态

     ⏳ 等待接入的会话 (1):
     • abc123ef - 用户12345 (等待3分钟)

     👤 您当前未接入任何会话

     💡 使用 /客服接入 <会话ID> 接入等待中的会话
```

### 3. 管理员接入会话

```
管理员: /客服接入 abc123ef
Bot: ✅ 成功接入客服会话
     会话ID: abc123ef
     用户ID: 12345
     创建时间: 2024-01-15 14:30:25
     问题描述: 我遇到了登录问题

     💡 现在您可以直接发送消息与用户交流
     使用 /客服状态 查看会话详情
```

### 4. 双向消息转发

**用户发送消息:**
```
用户: 我无法登录到系统
Bot (发给管理员): 👤 用户消息 [会话ID: abc123ef]
                   用户ID: 12345
                   内容: 我无法登录到系统

                   💡 回复此消息将转发给用户
```

**管理员回复:**
```
管理员: 请检查您的用户名和密码是否正确
Bot (发给用户): 🛠️ 客服回复: 请检查您的用户名和密码是否正确
```

### 5. 结束会话

```
用户: /退出客服
Bot: ✅ 已退出客服会话，感谢您的使用

管理员收到: ℹ️ 客服会话已结束
            会话ID: abc123ef
            用户ID: 12345
            会话时长: 5分30秒
```

## 技术架构

### 实现的消息功能

✅ **send_message_to_user**: 向用户发送消息  
✅ **send_message_to_admin**: 向管理员发送消息  
✅ **send_notification_to_admin**: 向指定管理员发送通知  
✅ **broadcast_to_admins**: 向所有管理员广播通知  
✅ **notify_admins**: 通知所有管理员新的客服请求  
✅ **forward_user_to_admin**: 转发用户消息给管理员  
✅ **forward_admin_to_user**: 转发管理员消息给用户  

### 技术实现

- 使用 AstrBot 的 `Context.send_message()` 方法实现消息发送
- 通过 `MessageChain` 和 `Plain` 组件构造消息内容
- 支持所有 AstrBot 支持的平台（QQ、Telegram、WeChat 等）
- 自动解析 `unified_msg_origin` 并路由到正确的平台

### 核心组件

1. **SessionManager**: 会话生命周期管理
2. **AdminManager**: 管理员权限和通知管理
3. **MessageForwarder**: 双向消息转发
4. **CustomerServicePlugin**: 主插件类，协调各组件

### 会话状态

- `WAITING_FOR_ADMIN`: 等待管理员接入
- `ADMIN_CONNECTED`: 管理员已连接
- `ENDED`: 会话已结束

### 超时机制

- **用户等待超时**: 30分钟（无管理员接入时）
- **活跃会话超时**: 60分钟（管理员接入后）
- **自动清理间隔**: 5分钟

## 配置要求

### 管理员设置

使用 AstrBot 的内置管理员配置：

1. 使用 `/sid` 命令获取用户ID
2. 使用 `/op <user_id>` 命令设置管理员
3. 管理员设置完成后即可使用客服接入功能

### 权限说明

- **普通用户**: 可使用 `/转人工` 和 `/退出客服` 命令
- **管理员**: 可使用所有命令，包括 `/客服接入` 和 `/客服状态`

## 注意事项

### 当前实现限制

1. **消息转发机制**: 当前版本在消息转发方面有一定限制，需要根据具体的平台适配器实现真实的消息发送
2. **通知系统**: 管理员通知主要通过 `/客服状态` 命令查看，自动推送通知需要进一步开发
3. **持久化**: 会话数据目前存储在内存中，重启后会丢失

### 部署建议

1. 确保系统中至少配置了一个管理员账号
2. 建议定期使用 `/客服状态` 查看待处理的会话
3. 在生产环境中建议实现持久化存储和消息推送机制

## 开发扩展

### 自定义消息格式

可以修改 `MessageForwarder` 类中的格式化方法来自定义消息显示格式。

### 添加持久化

可以扩展 `SessionManager` 类，添加数据库支持来实现会话持久化。

### 实现推送通知

可以扩展 `NotificationManager` 类，实现向管理员的主动推送通知。

## 故障排除

### 常见问题

1. **"暂无客服在线"**: 检查是否已配置管理员账号
2. **会话接入失败**: 确认会话ID正确且会话仍然活跃
3. **消息转发异常**: 检查网络连接和平台适配器状态

### 调试方法

1. 使用 `/客服状态` 查看系统状态
2. 查看 AstrBot 日志获取详细错误信息
3. 确认管理员权限配置正确
